# yisi-磁盘工具

带图形界面的磁盘数据恢复工具：找回删除的文件、按文件类型深度恢复、找回丢失的分区、制作能识别坏区的磁盘镜像。扫描、浏览和制作镜像都只读源盘，找回的文件和镜像一律保存到另一块盘上。

**下载最新版：<https://github.com/yisi-code/Yisi-Disk/releases/latest>**

## 能做什么（v0.3.0）

| 功能 | 说明 |
|---|---|
| 找回删除的文件 | 浏览 FAT12/16/32、exFAT、NTFS 与 Linux 的 ext2/3/4 分区的目录，列出已删除的文件，判断能不能完整找回，另存到别的盘；可以只选某个文件夹，直接看它里面删掉的文件；原来所在的文件夹已找不到的文件集中列在「找不到原目录的文件」里（NTFS 扫主文件表时自动找出，FAT、exFAT 可以按需读一遍空闲空间找回）；NTFS 压缩与 Windows 系统压缩（`compact /exe`、CompactOS）的文件读时解开；NTFS 上主文件表记录已被重用或清掉的已删除文件，从日志（`$LogFile`）里找回名字、上级文件夹与删除前的数据位置，标为「来自日志」（日志只留最近的操作，只找回了名字的列出、不能另存）。ext2 删除的文件按 inode 里留下的块指针读出；ext3、ext4 删除时清空了文件的位置，只列出名字、标明读不出 |
| 按文件类型深度恢复 | 不依赖文件系统，按文件结构在整块盘或镜像里找文件，目前 43 种格式：照片与图片（JPEG、PNG、GIF、BMP、WebP、HEIC、TIFF 与佳能、尼康、索尼、富士等相机原片、Photoshop、图标与光标、EMF / WMF 图元文件）、文档（PDF、Word / Excel / PowerPoint 新旧两种、OpenDocument、EPUB、DjVu、CHM 帮助）、压缩包与光盘镜像（ZIP、7z、RAR、CAB、TAR、gzip 与 tar.gz、ISO）、音视频（MP4、MOV、MKV、WebM、AVI、WMV / WMA、FLV、SWF（未压缩与 zlib 压缩的）、MP3、FLAC、WAV、AIFF、Ogg / Opus、MIDI、M4A）、Outlook 数据文件（PST / OST）、SQLite 数据库、Windows 程序与程序库（EXE / DLL）、字体（TrueType / OpenType、WOFF）、Windows 事件日志与注册表配置单元；按内容定扩展名（压缩包里装的是 Word 文档就存成 .docx）；可选「部分恢复」，后半段被覆盖或读不出的照片、音视频、压缩包等按结构还对得上的那一段存下，标为不完整。可以先扫描、预览，再挑着保存；扫描记录一直留着，程序关掉以后还能接着挑选保存，停下的扫描从停下的地方接着扫 |
| 找回丢失的分区 | 找出分区表里已经没有的 FAT、exFAT、NTFS、ext2/3/4 分区（ext 的主超级块坏了也能按块组开头的备份找到）：快速搜索只看分区通常开始的位置，几秒就能搜完；没找到时用深度搜索从头读一遍盘，边搜边列出、随时可以停止；NTFS 分区的主备引导扇区都没了也能按主文件表找回来浏览。浏览并另存里面的文件；也能把找到的分区写回分区表（ext 分区暂不写回），落在扩展分区里的写成逻辑分区（写前存备份、确认后才写、可以回滚） |
| 修复打不开的分区 | 诊断各分区的引导扇区与备份；主引导扇区坏了、备份完好时按备份打开，把文件另存出来；也能用备份修复主引导扇区或用主引导扇区重写备份；主备都坏了时按分区里留下的结构（FAT、根目录、主文件表）推算出引导扇区，先按它浏览、另存文件，再重建写回；主 GPT 或备份 GPT 坏了时用完好的一份修复另一份；分区类型与文件系统不符时改回（含逻辑分区）（FAT12/16/32、exFAT、NTFS；镜像文件或整块磁盘，Windows 所在的盘不写；写前存备份、确认后才写、写完读回核对、可以回滚） |
| 检查文件系统 | 只读检查 FAT、exFAT 的引导区、FAT 链、分配位图与目录项是否一致，NTFS 的引导扇区、主文件表与副本、每条记录、目录索引与簇的分配，列出问题与修法；丢失簇（先另存到别的盘）、断链、交叉链接、两份 FAT 不一致（先预演两种方向）、目录项与长文件名、分配位图漏标、过长的 FAT 链、读不出的空闲簇（标成坏簇）、exFAT 的大写表（写回标准表）与分配位图本身（按目录树重建）、FSInfo 与未正常卸下的标记可以勾选修复，NTFS 的主文件表与它的副本对不上时可以互相修复（都是先存写前备份、确认后才写、可以回滚） |
| 坏道检测 | 从头到尾读一遍盘，列出读不出的区段 |
| 制作磁盘镜像 | 先读完完好区域、最后才回头细读坏区，坏区位置记在坏区图里，扇区图边做边显示读到哪、哪里读不出；可以暂停、停止、之后接着做，可以按分区多选、分几次做；每次读多少、读错跳过多少、读得慢先跳过、坏扇区重读几遍、多久读不成功就停下都可以调 |

来源可以是镜像文件（raw / dd，或取证常用的 E01，E01 选第一段、其余各段放在同一文件夹）、整块磁盘，也可以只选其中一个盘符（如 D:）。E01 只读：找回文件、深度恢复、找分区、诊断、检查、坏道检测、以它为源制作镜像都可以直接用，要修复时先用「制作磁盘镜像」转成普通镜像。读盘时如果碰上损坏的区域（读不出或读得很吃力），界面会提示先制作镜像，再在镜像上操作。

## 下载与运行

1. 打开 [最新版本](https://github.com/yisi-code/Yisi-Disk/releases/latest)，下载 `yisi-disk-tools-v<版本>-windows-x64.zip`（GitHub 的下载文件名不能带中文，所以压缩包用英文名）。
2. 解压到任意位置（不要放在要恢复数据的那块盘上），得到 `yisi-磁盘工具-v<版本>-windows-x64` 文件夹，双击里面的 `yisi-磁盘工具.exe` 运行。
3. 文件夹里的 `yisi-engine.exe`、`yisi-broker.exe` 由主程序按需启动，三个程序要放在一起。
4. 以后有新版本时，在「关于」里点「检查新版本」→「下载并更新」：程序核对新版本的签名、大小与摘要后换上并重启，`data` 里的记录不动；有任务在运行时不能更新。也可以照第 1 步手动下载、解压替换。v0.2.0 及更早的版本没有这个功能，要手动换到 v0.3.0 一次。
5. 程序写的东西（做过的镜像、写盘记录与备份、打开文件时的临时副本、界面缓存）都放在程序文件夹里的 `data` 文件夹，不写到系统的 AppData。所以程序文件夹要放在能写入的位置；删掉整个文件夹就是彻底删除。

运行要求：

- Windows 10 或 11（64 位），需要 WebView2 运行时（Windows 11 自带；Windows 10 一般已随 Edge 装好，没有时从微软官网安装）。
- 读取磁盘或盘符时会弹出管理员权限请求（UAC），本次运行期间只请求一次；只处理镜像文件时不需要。

使用建议：

- 找回的文件、做出的镜像不能保存回正在读的地方：选整块盘时要存到另一块磁盘，只选一个盘符时存到别的盘符即可；程序会拦住保存回去的操作。
- 盘有坏道或读起来很慢时，先用「制作磁盘镜像」把盘复制出来，再在镜像上找回文件。

## 从源码构建

### 开发环境

| 需要 | 说明 |
|---|---|
| Rust | stable，`rustup` 安装 |
| Node.js 与 pnpm | Node.js 22、pnpm 10 |
| Visual Studio 生成工具 | 「使用 C++ 的桌面开发」组件与 Windows SDK |
| WebView2 | Windows 11 自带 |

### 开发模式

在 `app/ui` 目录下：

```bash
pnpm install
pnpm tauri dev
```

- 第一次运行要编译全部 Rust 依赖，需要几分钟；之后是增量编译。
- `pnpm tauri dev` 先编出引擎（`yisi-engine`）和磁盘代理（`yisi-broker`），再启动界面的开发服务器（`http://127.0.0.1:1420`）并打开窗口。改界面代码会自动刷新；改了引擎或代理，要退出后重新运行。

### 构建可执行程序

在 `app/ui` 目录下：

```bash
pnpm tauri build --no-bundle
```

产物在仓库根目录的 `target/release/` 下：`yisi-app.exe` 是主程序（发布时改名为 `yisi-磁盘工具.exe`），`yisi-engine.exe`、`yisi-broker.exe` 要和它放在同一目录。

### 检查与测试

在仓库根目录：

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

在 `app/ui` 目录下：

```bash
pnpm typecheck
```

每次推送到 `main` 和每个拉取请求，GitHub Actions 会在干净的 Windows 环境里从头跑一遍界面构建（含类型检查）、格式、clippy 与全部测试（`.github/workflows/ci.yml`）。
